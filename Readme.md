# Ikigai OS 🌱

> A local-first personal growth operating system that turns daily tasks, milestones, and reflection into an interactive calendar, evolving garden, and living record of progress.

Ikigai OS is an experimental personal productivity and life-tracking application built around a simple idea:

> **Plan → Do → Complete → Reward → See your world change.**

Instead of behaving like a traditional task manager, Ikigai OS is designed to feel like a **place you return to every day** — part planner, part journal, part progress system, and eventually part living digital garden.

---

## ✨ Why Ikigai OS?

Most productivity tools are good at storing tasks.

Ikigai OS is being built to make progress **visible, memorable, and emotionally rewarding**.

The long-term vision includes:

- a task-driven daily system
- a physical, tear-off style interactive calendar
- seasonal themes and visual customization
- an evolving garden that grows from completed work
- weekly and monthly reflections
- memories and personal milestones
- project, certification, and career tracking
- optional local AI assistance
- local-first data ownership with optional sync later

The goal is not to gamify life for the sake of points.

The goal is to create a system where **real effort leaves visible evidence**.

## 🌱 The Core Loop

```text
Plan / capture something
        ↓
Do the work
        ↓
Complete / reflect / preserve proof
        ↓
Ikigai records the history locally
        ↓
Today · Journey · Sanctuary · Reflection · Memory · Career
become different views of the same lived progress
```

Ikigai is task-first where tasks are useful, but the product is broader than a reward counter. Roadmap progress, reflections, memories and proof also leave visible traces without requiring the user to maintain a second gamification dataset.

## 🌿 Sanctuary Philosophy

The original single-seed Garden has evolved into **Sanctuary**: an optional 3D spatial expression of the same local data already stored elsewhere in Ikigai.

- completed tasks enrich Home Grove;
- reflections enrich Moon Pond;
- memories become abstract light/lantern traces without exposing their private text;
- Roadmap progress develops the route to The Lookout;
- Career/Proof develops a beacon/work structure;
- achievements can become discoverable physical landmarks.

Sanctuary does not become a second system the user has to feed. The world is derived from existing records, uses hard rendering caps, supports reduced motion/performance controls, and remains optional.

The Familiar exists as the same character identity in page UI and Sanctuary. It has no hunger/streak/guilt mechanics.

## 📅 Daily + Journey Direction

Today and Journey now share one desk metaphor. Today is the open notebook: tasks are written directly on the left page and one optional day note lives on the right. If enabled in Settings → Experience, the existing paper-physics Daily Page also sits on the desk as a small physical object: today's sheet can be lifted and flexed but cannot tear, while an older open sheet can be torn only after carry-forward choices are confirmed. Reduced Motion makes the sheet display-only, and the Morning Handoff remains available when enabled.

Journey is the broader calendar desk. There is no permanent date inspector. Clicking a date pulls out a temporary paper sheet for tasks, a note and markers; future/today tasks can be written directly there. Month pages can be pulled horizontally or changed through normal accessible controls.

## 🧠 Local-First by Design

Ikigai OS is intentionally being built as a **local-first application**.

Your primary data lives on your device.

Current architecture:

```text
React UI
   ↓
Application data layer
   ↓
Dexie
   ↓
IndexedDB
   ↓
Your device
```

### Current privacy model

- no login required
- no mandatory cloud account or remote database
- life-data remains local by default
- backup/export is user initiated
- remote AI is optional and configured explicitly
- custom remote AI origins require an explicit trust decision before receiving a key
- remembered provider credentials remain outside backup/export

A future sync provider can use the existing local sync queue, but the current product does not silently upload the local database.

## 🎨 Design Direction

Ikigai is not intended to become a conventional productivity dashboard. Different rooms may use different physical/spatial metaphors, but they should share one interaction language.

Current principles include:

- clear information hierarchy before decoration;
- progressive disclosure instead of demanding every field up front;
- tactile stationery/desk metaphors for Daily and Journey;
- Sanctuary as the dedicated 3D world rather than making every page WebGL;
- a stable Familiar character system rather than a roaming chatbot button;
- calm motion with full reduced-motion equivalents;
- immersive moments without hiding core actions;
- no guilt mechanics, hunger bars or artificial pressure;
- local-first data ownership and explicit network boundaries.

---

## 🔐 Data Ownership

Ikigai is local-first. Live life-data is stored in IndexedDB and can be exported as a user-controlled integrity-checked JSON backup with embedded Vault attachment data. Restore supports merge and replace modes with structural/checksum preflight and transactional writes.

Remote AI is opt-in and separate from backup. Remembered provider credentials are never exported by Ikigai. Custom remote AI origins require explicit trust before receiving a key.

The goal remains simple:

> **Your data should not leave your device unless a feature clearly requires it and you explicitly choose that feature/provider.**

See `DATA_SAFETY.md` and `SECURITY.md` for the implemented boundaries and limitations.
