WHAT CHANGED
============

1) First Light · Protected Dates
- Replaced the Chromium/Windows native date picker with an Ikigai-owned segmented DD / MM / YYYY control.
- DD, MM and YYYY are directly editable and select cleanly on focus.
- Partial manual input stays visible while editing instead of being cleared mid-entry.
- Added a themed month calendar with previous/next month, Today, Clear, selected-date and today states.
- Replaced the native <select> milestone type menu with an Ikigai-styled Event / Deadline / Exam / Release / Other popover.
- The stored data contract is unchanged: completed dates remain YYYY-MM-DD strings.

2) First Light · Text-size live preview
- 90% / 100% / 115% / 130% now visibly affect First Light itself, including the Arrival introduction.
- Existing desktop/mobile base typography has been preserved and scaled rather than replaced with one generic font size.
- Larger accessibility scales can continue to use the app's existing scroll/fallback behavior.

3) First Light · Familiar live preview
- Added the real reusable FamiliarAvatar to the Familiar setup step.
- Form, material, aura, presence and nook-side changes now update the preview immediately.
- Home-only keeps a visible explanatory preview rather than making the Familiar mysteriously disappear.
- No Familiar progression/economy behavior was added.

4) First Light · Paper & Time live preview
- Filled the previously empty visual area with a live Daily Paper + Journey calendar preview.
- Reuses the project's DailyCalendarPreview and Journey calendar visual grammar instead of inventing unrelated mock art.
- Theme changes are presentation-only and do not alter archived/planning dates.

5) Sanctuary · Explore mode
- Added an explicit Explore toggle to the Sanctuary region strip.
- In Explore mode: WASD gently wanders the camera target, drag looks around, wheel changes viewing distance.
- Movement is bounded to a Sanctuary island radius and follows terrain height.
- Reset view remains available; entering Stillness, travelling to a preset region, or starting the guided tour exits free Explore.
- No sprinting, jumping, stamina, minimap, score, XP or other game mechanics were introduced.

6) Spotify · in-app setup guide
- Added an expandable step-by-step guide inside Now Playing > Source.
- Suggested Spotify developer app values:
  App name: Ikigai OS
  Description: Personal local-first life OS with a private Now Playing view using Spotify playback metadata.
  Website: https://ananta-sj.github.io/ikigai-os/
  API / SDK: Web API
- Added copy controls for the suggested values and exact redirect URI.
- Clearly tells the user to paste the Client ID only, never the Client Secret.
- Explains Authorization Code + PKCE, view-only vs playback-control permission, local token remembering, and current Development Mode / allowed-user expectations.

7) Spotify · installed Windows OAuth return path
- Browser/PWA behavior remains on its existing web redirect flow.
- The Tauri app now uses an explicit 127.0.0.1 loopback callback for Spotify OAuth.
- The registered native redirect shown to the user is:
    http://127.0.0.1/spotify/callback
- During an actual native sign-in Ikigai reserves an ephemeral local port and sends that port in the authorization request. Spotify explicitly permits dynamic ports for loopback IP literals when the registered redirect omits the port.
- Added a small Tauri Rust listener which accepts the OAuth result only on /spotify/callback, emits it back to the Ikigai WebView, returns a tiny local completion page, then stops.
- Native authorization opens in the user's default browser.
- The native open-url command is allowlisted to Spotify authorization rather than becoming a general arbitrary URL launcher.
- PKCE remains the security model; no Spotify Client Secret is stored in the app.

SPOTIFY REFERENCE NOTES
=======================
The implementation follows Spotify's current official Redirect URI and Authorization Code with PKCE guidance:
- redirect URI must match the registered value, except that loopback IP literals may use dynamically assigned ports;
- explicit 127.0.0.1 / [::1] loopback addresses may use HTTP;
- localhost is not accepted;
- PKCE is the appropriate flow when a desktop/browser client cannot safely store a Client Secret;
- current Development Mode requires Premium for the app owner and limits authorized users.
